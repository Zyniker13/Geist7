# Rosette — Screenshot Plan and Record

App Store screenshots are generated by UI tests on simulators (conventions
§P10) and exported from the test result bundle. Sizes: the iPad Pro 13-inch
set is primary (iPad-first), plus the iPhone set. Exact per-device pixel
sizes are normalized by the maintainer at upload (issue #11).

## Shots (same set on both devices)

1. **Match start** — fresh board, pre-roll hint, stake shown.
2. **Mid-match rosette landing** — a piece on the central rosette with the
   extra-roll banner visible.
3. **Capture** — an opponent piece sent home; log line visible.
4. **Doubling cube offered** — the cube prompt over a live board.
5. **Circuit map** — the tavern route Ur → Thebes → Tenochtitlan with the
   current stop highlighted.
6. **Daily challenge** — the daily board with a rolled result.

## Capture mechanism

`Tests/Snapshots/Snapshots.swift` (placeholder in the repo) drives the app
with launch arguments to reach each state deterministically (fixed seed),
takes `XCUIScreen.main.screenshot()`, attaches each with lifetime
`.keepAlways`, and the PNGs are exported from the `.xcresult` with
`xcresulttool export attachments`. Captures run on:

- `zGeist7_bot-iPad-Pro-13` (iPad Pro 13-inch, iPadOS 27.x)
- `zGeist7_bot-iPhone-17` (iPhone 17, iOS 27.x)

Both devices are created by this bot (`simctl create`); sim-lock wraps every
run. Captured PNGs land in `docs/release/screenshots/` with the device and
shot number in the filename.
