## Module Diagram

```
Rosette-iOS / Rosette-macOS (App: SwiftUI)
  RosetteApp → MainView (menu) → GameView (match screen)
  GameViewModel (@MainActor, ObservableObject)
        │ calls
        ▼
  RSCore ── Reducer (pure: Action × MatchState → (MatchState, [Event]))
  ▲  │      MoveGen · Rosette · Wager · Odds · Solve (UrSolver/UrRanking)
  │  │      Foundation: SeededRNG (SplitMix64) · Fixed (Q32.32)
  │  ▼
  │  RSRender ── BoardScene (SpriteKit scene; renders MatchState)
  │  RSContent ── ruleset/omen/scenario tables (JSON-driven, P3+)
  │  RSAI ── difficulty tiers (P4; the P2 heuristic lives in GameViewModel)
  │  RSAudio ── AVFoundation SFX/music (P6)
  │  RSPlatform ── haptics/settings/file abstraction (P7)
  │  RSMeta ── circuit, purse, statistics (P5+)
  └────────── dependencies all point inward to RSCore
```

- **App** depends on all seven packages. Packages depend only on RSCore (and each other as the phase work lands; RSRender on RSCore only).
- The Xcode project is generated by XcodeGen from `project.yml`; the `Makefile` drives `gen`/`build`/`test`/`lint`/`sim`/`todo`.

## Data Flow

1. **Input → Action.** SwiftUI controls (`GameView`) and the SpriteKit board (`BoardScene.onSquareTap`) call `GameViewModel` methods (`rollDice()`, `movePiece(_:)`, `offerDouble()`, `acceptDouble()`, `concede()`). Each maps one-to-one onto an RSCore `Action`.
2. **Action → reducer.** `GameViewModel.applyAction(_:)` calls `Reducer.apply(action, to: matchState, rng: &rng, omenRng: &omenRng)`. The reducer owns all rules: legality (R-3–R-5), capture (R-5), rosette extra rolls (R-6/R-19), bear-off and outcome (R-7/R-8), cube (R-9–R-11), omens (R-12), turn passing. Illegal actions throw `RuleError`, surfaced as `errorText`.
3. **State → render.** `matchState` is `@Published`; SwiftUI re-renders the HUD (dice, cube, odds panel, stake) and `BoardScene.matchState` is reassigned so the scene re-renders squares, pieces, rosettes, and legal-move highlights from `MoveGen.legalMoves`.
4. **Events → feedback.** `result.events` are folded into `lastEventText` ("Rolled 3", "Capture!", "Rosette! Extra roll", …) and become the seam for audio/haptics in P6.
5. **Persistence.** After every applied action the ViewModel autosaves a `SavedMatch` (or deletes it on completion).

Determinism contract: two streams only — `rng` for dice, `omenRng` for omen draws — both seeded from one seed (the omen seed is `seed &+ 0x9E37_79B9_7F4A_7C15`). `Date()`, `UUID()`, `Float.random`, and other nondeterminism are banned in RSCore and enforced by `Tools/check-imports.sh`.

## Threading Model

- `GameViewModel` is `@MainActor`; all `Reducer.apply` calls and `@Published` mutations happen on the main actor.
- The AI (P2 heuristic; P4 tiers later) schedules its next step with `DispatchQueue.main.asyncAfter` on the main actor — the engine stays single-threaded at runtime.
- SpriteKit scene updates happen from the main actor (SwiftUI `updateUIView`/`updateNSView`); the scene is read-only over `MatchState`.
- RSCore's state types are Swift value types; the solver (`UrSolver`) is a batch tool (`Tools/SolveUr`) and runs outside the UI process entirely.
- Long AI computations (P4) must go through time budgets on a background queue with results applied back on the main actor (roadmap §7).

## Save Format

`SavedMatch` (Codable JSON, schema version 1) in `Documents/RosetteSaves/`:

```json
{
  "version": 1,
  "seed": 42,
  "stakeValue": 1,
  "omenId": null,
  "useAI": true,
  "actions": [{"roll": {}}, {"move": {"_0": 0}}]
}
```

- Restore is **deterministic replay**: rebuild the initial `MatchState` from the stored configuration, then fold `actions` through `Reducer.apply` with fresh streams from the stored seed. INV-4/INV-7 guarantee the restored state is bit-identical to the saved one; the action history is the save, not the board.
- The autosave slot is overwritten every action; manual saves carry a wall-clock timestamp in the file name only (naming, not state).
- The same shape is the replay format used by `Tools/sim`'s golden fixtures (S1.4), so one format serves saves, replays, and CI evidence.
